# AZ CAT Translation Memory - Rebuilt V1

هذه نسخة معاد بناؤها من أداة CAT بحيث لا تُحمّل الوظائف الثقيلة عند فتح الواجهة. الواجهة تظهر فوراً، ثم يتم تحميل وحدات الاستيراد والتحليل عند استخدامها فقط.

## أهم ما تم تنفيذه

1. واجهة مستقلة سريعة `index.html` مناسبة للرفع على GitHub/Vercel.
2. تقسيم الكود إلى وحدات:
   - `src/main.js` للربط العام والواجهة.
   - `src/storage.js` للتخزين في IndexedDB.
   - `src/importers/*` لاستيراد HTML / DOCX / ZIP DOCX / XLSX / TMX.
   - `src/workers/analyze.worker.js` للتحليل الثقيل خارج واجهة المستخدم.
   - `src/core/*` للتطبيع والتقسيم والتقييم.
3. التحليل يعمل داخل Web Worker حتى لا تتجمد الصفحة أثناء تحليل النصوص الكبيرة.
4. استيراد الذاكرة يُحفظ على دفعات داخل IndexedDB.
5. عرض النتائج بنظام صفحات بدلاً من رسم آلاف النتائج دفعة واحدة.
6. منطق مطابقة مبدئي:
   - exact normalized.
   - exact compact.
   - fuzzy score.
   - split composite للنصوص الطويلة عند وجود الذاكرة مقسّمة في عدة خلايا.
7. تصدير النتائج إلى HTML أو CSV، ونسخ Target Draft.

## طريقة الاستخدام على Vercel أو GitHub Pages

ارفع مجلد المشروع كاملاً كما هو. لا توجد خطوة بناء ولا توجد مكتبات خارجية.

الملف الرئيسي هو:

```text
index.html
```

## ملاحظات مهمة

- استيراد DOCX وXLSX محلي بالكامل ويعتمد على دعم المتصفح لـ `DecompressionStream`. الأفضل تشغيله على Chrome أو Edge حديث.
- هذه النسخة لا تستخدم أي CDN ولا API خارجي.
- لا تضف ترقيعات كثيرة فوقها. إذا أردت ميزة جديدة، أضفها كوحدة مستقلة داخل `src` ثم اربطها من `main.js`.
- Export Target HTML يحافظ على جدول مرتب للـ Source/Target، لكنه ليس إعادة بناء كاملة لملف Word الأصلي. إعادة بناء DOCX بنفس تنسيق المصدر 100% تحتاج مرحلة مستقلة مخصصة لمعالجة `document.xml` ونسخ أنماط Word.

## المسار المقترح للمرحلة التالية

1. إضافة Export DOCX يحافظ على تنسيق source كاملاً.
2. جعل الذاكرة لا تُرسل كاملة إلى Worker عند كل تحليل، بل بناء فهرس دائم مخزن في IndexedDB.
3. إضافة شاشة QA: أرقام، أقواس، مصطلحات إلزامية ومحظورة.
4. إضافة إعدادات Threshold للمطابقة.
